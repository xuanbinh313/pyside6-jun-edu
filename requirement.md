# Project Refactoring Guidelines: PySide6 MVVM Architecture

## 1. Directory Structure Standards
- `src/`: Contains all business logic, ViewModels, and View implementation classes.
- `ui/`: Contains raw `.ui` files generated by Qt Designer.
- `ui_gen/`: Contains auto-generated Python files (`ui_*.py`) created by `pyside6-uic`.
- **Constraint:** Treat `ui_gen/` as a read-only directory. Never manually edit these files.

## 2. Refactoring Rules
- **Import Strategy:** Always import UI classes from `ui_gen`. 
  *Example: `from ui_gen.ui_main_window import Ui_MainWindow`*
- **UI Decoupling:** Keep `src/views/` clean by separating UI setup from business logic. Implement all custom widget behavior (signals, slots, styling) in the view class that inherits from the generated UI class.
- **Auto-Generation:** If you modify a UI, regenerate the Python file using:
  `pyside6-uic ui/your_file.ui -o ui_gen/ui_your_file.py`

## 3. Robust Logic & Error Handling
- **NoneType Protection:** Since generated UI files can contain `None` references (especially when using `findChild` or complex layouts), always check for existence before interacting with widgets.
- **Safe Layout Cleanup:** Use recursive approaches to clear layouts, handling `QSpacerItem`, `QLayout`, and `QWidget` items separately to avoid `NoneType` attribute errors.
- **Lifecycle:** Ensure `setupUi(self)` is called before any custom signal-slot connections or widget property overrides.

## 4. Signal & Slot Management
- **ViewModel Decoupling:** ViewModels should not import `QtWidgets`. They should only use `PySide6.QtCore` components (like `Signal` and `QObject`) to communicate data changes to the View.
- **Signal Blocking:** Use `blockSignals(True)` during programmatic UI updates (e.g., when populating a table or a dropdown list) to prevent redundant event triggering.

## 5. Tooling & Automation
- **Code Quality:** Utilize `ruff` to maintain code standards.
  *Command:* `python -m ruff check . --fix`
- **Execution:** Always run scripts or tools via `python -m <module>` to ensure compatibility with the `.venv` structure and avoid PATH issues.
